# Релиз: Glassdoor — надёжность, новые фильтры, исправление определения Remote

**Дата:** 5 апреля 2026

---

## Что изменилось и почему

Glassdoor как источник работал нестабильно: запросы часто заканчивались ошибкой 403 от Cloudflare, фильтр удалённой работы не работал на уровне API, а часть вакансий ошибочно помечалась как Remote. Весь слой работы с Glassdoor переработан с прицелом на стабильность и корректность результатов.

---

## Изменения в деталях

### 1. Устранена главная причина ошибки 403

**Было:** Glassdoor стоит за Cloudflare, который проверяет TLS-отпечаток браузера. Библиотека `tls_client`, которая использовалась ранее, давала приблизительный fingerprint — Cloudflare его распознавал и блокировал запросы.

**Стало:** Скрапер переведён на `curl_cffi` — библиотеку, которая использует ту же TLS-реализацию, что и реальный Chrome (BoringSSL). Cloudflare не может отличить такие запросы от браузера.

`curl_cffi` — опциональная зависимость. Если не установлена — скрапер падает обратно на `tls_client` с предупреждением:
```
WARNING: curl_cffi is not installed — falling back to tls_client.
Install it for better Cloudflare bypass: pip install curl_cffi
```

Установить: `pip install python-jobspy[cloudflare]`

---

### 2. Добавлен фильтр по формату работы (Remote)

Теперь при `work_format="remote"` в GraphQL-запрос к Glassdoor передаётся фильтр `remoteWorkType: "1"`. Это официальный API-фильтр — Glassdoor на своей стороне отсекает нерелевантные вакансии.

Совместимость с `is_remote=True` сохранена: если передан `is_remote=True`, фильтр тоже активируется.

---

### 3. Добавлен фильтр по уровню должности

Доступные уровни:

| Значение | API-ключ |
|---|---|
| `internship` | `"internship"` |
| `entry` | `"entrylevel"` |
| `associate` | `"entrylevel"` |
| `mid_senior` | `"midseniorlevel"` |
| `director` | `"director"` |
| `executive` | `"executive"` |

Glassdoor принимает одно значение уровня за раз — используется первый элемент из `seniority_levels`.

---

### 4. Исправлено ошибочное определение Remote-вакансий

**Было:** логика `locationType == "S"` → remote. Это неверно: вакансии с географическим охватом на целый штат (например, "California") тоже имеют `locationType = "S"`, но они не являются удалёнными.

**Стало:** вакансия считается Remote только если:
- `locationName == "Remote"` (явная метка), **или**
- `locationType == "S"` **и** `locationName` пустой

Это устраняет ложные срабатывания для onsite-вакансий уровня штата.

---

### 5. Устойчивость к частичным ошибкам API

Glassdoor иногда возвращает поле `"errors"` в ответе даже когда данные о вакансиях полностью присутствуют — это случается при сбоях второстепенных полей вроде `jobsPageSeoData` (DNS-ошибки на стороне Glassdoor).

**Было:** любое появление `"errors"` → исключение → страница не обработана.

**Стало:** ошибка считается критической только если отсутствует сам массив вакансий. Второстепенные ошибки логируются как предупреждение, скрапинг продолжается.

---

### 6. Исправлена устойчивость к ошибкам при поиске локации

AJAX-запрос для разрешения локации (`/findPopularLocationAjax.htm`) иногда возвращает 400 или 403 — особенно при запросах не из США.

**Было:** любой не-200 статус (кроме 429) → исключение → скрапер падал.

**Стало:**
- `429` → завершение с пустым результатом и ошибкой в лог
- `400` / `403` → fallback на worldwide-локацию (id=11047), поиск продолжается

---

### 7. URL-кодирование в запросе локации

`location="São Paulo"` или `location="Austin, TX"` теперь корректно кодируются в URL (`quote(location)`) перед передачей в AJAX-запрос.

---

### 8. Исправлен CSRF URL

CSRF-токен теперь берётся с главной страницы (`/`). Прежний URL `/Job/computer-science-jobs.htm` стал возвращать 404 (страница удалена). Токен в HTML присутствует на обеих страницах, но главная стабильнее.

---

### 9. Согласованность версии Chrome в заголовках

`sec-ch-ua` и `user-agent` теперь указывают одну и ту же версию Chrome (141). Ранее была рассинхронизация: `sec-ch-ua` указывал Chrome 118, `user-agent` — Chrome 138. Cloudflare использует это расхождение как сигнал бота.

---

### 10. Description-запросы через основную сессию

Запросы за описанием вакансий теперь идут через тот же `curl_cffi`-сеанс, что и основной поиск. Ранее использовался голый `requests.post()` — без правильного TLS-отпечатка и без поддержки прокси.

## Изменения в API библиотеки (для интеграции)

Этот раздел описывает всё, что изменилось в публичном интерфейсе `scrape_jobs()` и в структуре возвращаемых данных. Если в проекте есть агенты или код, который вызывает JobSpy — нужно проверить совместимость по этому разделу.

---

### Новые параметры `scrape_jobs()`

#### `work_format: str | None = None`

Фильтрует вакансии по формату работы. Работает для **Glassdoor** и **LinkedIn**.

```python
df = scrape_jobs(
    site_name=["glassdoor", "linkedin"],
    search_term="Python developer",
    location="USA",
    work_format="remote",  # "remote" | "hybrid" | "onsite"
)
```

**Важно:** для каждого формата нужен отдельный запрос. Передать несколько значений нельзя.

**Glassdoor:** фильтр применяется на стороне API (`remoteWorkType`). Только `"remote"` поддерживается API-фильтром — `"hybrid"` и `"onsite"` значения принимаются параметром, но Glassdoor API не имеет соответствующих ключей для них (фильтр просто не отправляется).

**LinkedIn:** фильтр применяется через параметры поиска.

---

#### `seniority_levels: list[str] | None = None`

Фильтрует вакансии по уровню должности. Работает для **Glassdoor** и **LinkedIn**.

```python
df = scrape_jobs(
    site_name="glassdoor",
    search_term="Engineer",
    seniority_levels=["mid_senior"],  # список уровней
)
```

Допустимые значения: `"internship"`, `"entry"`, `"associate"`, `"mid_senior"`, `"director"`, `"executive"`.

**Glassdoor:** используется только первый элемент списка — API принимает один уровень.

**LinkedIn:** поддерживает несколько уровней одновременно.

---

#### `linkedin_use_keyword_work_format_fallback: bool = True`

Только для **LinkedIn**. Если `True` — при отсутствии явного атрибута формата работы в вакансии библиотека ищет ключевые слова в описании (`"remote"`, `"hybrid"`, `"work from home"`). Если `False` — только явные атрибуты.

```python
df = scrape_jobs(
    site_name="linkedin",
    work_format="remote",
    linkedin_use_keyword_work_format_fallback=False,  # строгий режим
)
```

---

### Новое поле в результирующем DataFrame: `work_format`

Каждая вакансия в `df` теперь содержит колонку `work_format`:

| Значение | Смысл |
|---|---|
| `"remote"` | Удалённая работа (подтверждено) |
| `"hybrid"` | Гибридный формат (подтверждено) |
| `"onsite"` | Только офис (подтверждено) |
| `None` / `NaN` | Формат не определён из данных источника |

**Glassdoor:** `work_format` заполняется для всех вакансий. Remote определяется структурно по данным API. Все остальные вакансии получают `"onsite"` — Glassdoor API не различает onsite и hybrid, а оба формата предполагают физическое присутствие в офисе.

**LinkedIn:** `work_format` заполняется для всех вакансий, у которых атрибут есть в ответе API.

**Пример обращения к полю:**
```python
remote_jobs = df[df["work_format"] == "remote"]
unknown_format = df[df["work_format"].isna()]
```

---

### Изменилось поведение `is_remote`

`is_remote` остаётся в DataFrame и работает как раньше, но теперь **синхронизируется с `work_format`**:

- Если `work_format == "remote"` → `is_remote = True`
- Если `work_format` задан и не `"remote"` → `is_remote = False`
- Если `work_format` не определён (`None`) → `is_remote` берётся напрямую из данных источника (без изменений)

Обратная совместимость: `is_remote=True` в параметрах `scrape_jobs()` по-прежнему работает как раньше — он автоматически маппится в `work_format="remote"` внутри библиотеки.

---

### Установка зависимости для Glassdoor

Для стабильной работы Glassdoor требуется `curl_cffi`. Без неё скрапер упадёт обратно на `tls_client` и будет получать 403 от Cloudflare при большинстве запросов.

```bash
pip install python-jobspy[cloudflare]
# или напрямую:
pip install curl_cffi
```

Если в `requirements.txt` или `pyproject.toml` проекта прописан `python-jobspy` без экстра — нужно добавить `python-jobspy[cloudflare]` или отдельно `curl_cffi`.

### Что не изменилось (обратная совместимость)

- Все существующие параметры `scrape_jobs()` работают без изменений
- `is_remote=True` продолжает работать как раньше
- Структура DataFrame не сломана — добавлена только новая колонка `work_format`
- Indeed, ZipRecruiter, Google — их поведение не изменилось
- Если `curl_cffi` не установлен — библиотека продолжает работать (с деградацией для Glassdoor)
